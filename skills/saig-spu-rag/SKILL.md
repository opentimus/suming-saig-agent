# 数命SPU / SAIG 知识库检索

## 目的

把技能自带的 Markdown 文档封装为可离线、可独立分发的小型知识库：构建期一次性分块并建立索引，运行期毫秒级返回最相关的证据块，仅供内部核对事实，对用户自然作答、不展示来源，避免编造。

## 数据源

唯一事实源是 `references/` 目录下的 Markdown 附件，直接读取，不依赖任何外部文件或本地路径清单：

- `references/数命SPU说明.md` —— SPU 概念、五项核心能力、数命科技实践
- `references/数命SPU社区说明.md` —— 社区定位、人才培养、FDE/OPC 路径
- `references/SAIG数命SPU国际AI大赛说明.md` —— 大赛背景、赛制、报名与时间安排（材料内无奖项条款，问奖项时如实说明未覆盖）
- `references/武汉概览.md` —— 武汉地理、人口、经济、产业、文旅、风景名胜等背景
- `references/2026武汉旅游产品手册md.md` —— 武汉旅游产品手册：文博场馆、四季赏花、都市漫游、红色旅游、演艺空间、乡村休闲、湖光山色、科技研学、长江游览、汉派美食、线路攻略及各景点介绍

## 何时使用

出现以下任一情形时使用：

- 询问「SPU 是什么 / 五项核心能力 / 数命科技怎么实践」
- 询问「数命 SPU 社区 / FDE / OPC / 一人公司」
- 询问「SAIG 大赛 / 赛制 / 报名 / 时间安排」
- 询问《武汉概览》中的武汉背景（地理、人口、GDP、产业、景点、文化等）
- 询问武汉具体景点介绍、看点与游览体验（如黄鹤楼、文博场馆、演艺空间等）
- 询问四季赏花、汉派美食、科技研学、长江游览、乡村休闲、线路攻略等主题游内容
- 要求「根据大赛材料 / 竞赛资料 / 旅游产品手册 / 攻略资料回答、归纳、对比」


## 使用步骤

1. 以用户问题原文作为查询，调用检索脚本：

   ```bash
   python3 scripts/retrieve.py "用户的问题原文" 4
   ```

2. 读取返回的 JSON（按相关度降序）：每条含 `id / source / section / page / score / text`。其中 `source` 为 Markdown 文件名，`section` 为章节标题；Markdown 无页码，`page` 恒为 `null`。这些字段仅供内部核对。
3. 仅基于返回的 `text` 作答，不引入材料外的信息。
4. 以自己的话自然作答；不要向用户提及文件名、章节、页码或检索过程，检索内容只用于确保事实准确。
5. 结果为空时即视为材料未覆盖该问题：先换一种问法或补充关键词重试一次；仍为空就如实说明材料未覆盖，**不得用自身记忆补答或编造**。返回结果与问题明显不相关时同样按「未覆盖」处理，不要把无关内容硬套。

## 说明

- 检索为**章节加权 BM25**（BM25F 单字段近似：章节标题权重 4.5、正文 1.0），中文按「连续汉字串二元组 + 非停用单字」切分，英文/数字按词。默认纯 Python 标准库实现，无需联网、无需第三方依赖。
- 查询侧会剥离「介绍/一下/什么/怎么/多少」等意图词与疑问词，并做少量别名扩展（门票→票价、报名→参赛等），因此直接用自然语言提问即可，不必刻意堆关键词。
- 结果只保留命中词权重覆盖查询 30% 以上的块，同一章节去重，并限制单一来源占比，避免《2026武汉旅游产品手册》这类大文档挤掉其余材料。
- 可选增强：安装 `jieba` 后可用 `python3 scripts/build_index.py --tokenizer jieba` 构建分词更精细的索引；索引里记录了构建所用分词器，运行期不一致会直接报错提示，不会静默劣化。随包分发的索引固定为 `char-v2`（零依赖）。
- 检索结果仅供内部参考，不向用户展示来源、章节或检索过程。
- 知识库为预构建产物：`data/chunks.json` 与 `data/index.json`（格式 v3）。修改 `references/*.md` 后，运行 `python3 scripts/build_index.py` 重建索引与数据。
- 构建脚本自动扫描 `references/` 下全部 `.md` 文件，新增或替换文档无需改动代码。
- 检索召回依赖查询与文档的词汇重叠；同义改写覆盖有限时，可在查询中补充关键词。

## 资源

### scripts/

- `tokenizer.py` —— 构建期与运行期共用的唯一分词实现：停用字表、意图词剥离、别名扩展、可选 jieba，并提供 `tokenizer_id` 一致性与校验。
- `build_index.py` —— 扫描 `references/*.md`、Markdown 感知分块、章节加权并构建 BM25 索引（构建期一次性运行）。
- `retrieve.py` —— 运行期检索入口，入参为查询字符串与可选 top_k，输出 JSON。

### references/

- 上述 5 份 Markdown 文档，既是检索数据源，也可直接阅读以补充上下文。

### data/

- `chunks.json` —— 分块及其来源、章节标题与章节路径（`section` / `section_path`）。
- `index.json` —— 章节加权 BM25 倒排索引（v3：含 `tokenizer` 签名、扁平倒排表 `[doc_id, tfw, …]` 与 `doc_len`）。
