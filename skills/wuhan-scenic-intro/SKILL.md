# 武汉旅游咨询技能

## 目的

作为**武汉旅游咨询的默认入口**承接用户问题。分流只有一条**技能间**规则，其余一律由本技能处理：

| 排除项 | 说明 | 交给谁 |
| --- | --- | --- |
| 武汉城市基本历史与地情信息 | 自然地理、建置沿革、人口经济、方言民俗、科教交通等地方志内容 | `wuhan-intro` |
| 需要生成结构化行程单 | 「几日游怎么安排」「生成完整行程单」「某条线路包含哪些景点」 | `wuhan-route-query` |

排除上表之后，武汉游玩咨询类问题都归本技能，例如：

> 点到点导航、实时路况、驾车/公交具体走法**不属于任何技能的能力范围**（相关技能已下线）：遇到「从 A 怎么到 B、要多久」类问题，可据景点片区给出串联建议并标注为建议，同时提示用户用地图 App 核实，不得编造距离与耗时。

- 景点详情与看点玩法：「详细介绍一下东湖绿道」「武汉大学有什么看点」「昙华林值不值得去」
- 主题与季节推荐：「带爸妈来武汉玩点什么」「樱花季什么时候最好看」「拍照最好的地方」
- 比较与取舍：「省博物馆和武汉博物馆去哪个」「黄鹤楼和晴川阁怎么选」
- 讲解词、打卡清单、短介绍撰写
- 景点所属 G1-G9 线路及同线串联景点

## 信息范围

| 可提供的信息 | 内容要点 | 获取方式 |
| --- | --- | --- |
| G1-G9 路线简单介绍 | 线路定位、串联景点、起止片区、参考总时长 | 直接读 @references/route_overview.md，**不调用接口** |
| 景点详细介绍 | 历史背景、看点特色、推荐指数与点评、建议停留时长 | Dify 知识库接口（`scripts/query_scenic.py`） |
| 景点关联路线介绍 | 该景点所属的 G1-G9 线路，及同线串联景点 | 先查 @references/route_overview.md 速查表 |
| 玩法、主题、季节、讲解词等泛旅游咨询 | 以知识库返回的资料为准组织回答 | 同上接口，query 用用户原始问题 |

**知识库的真实边界（实测）**：该知识库收录的是武汉景区介绍类资料，即使问「门票多少钱」「几点开门」，返回的仍是景点沿革与看点文本，**并不包含票务、开放时间、实时客流数据**。因此：

- 涉及票价、开放时段、预约政策、实时状态的问题，仍调用接口，但回答时**必须说明知识库未提供该信息，建议出行前核实官方渠道**，不得引用接口文本里没有的数字，也不得凭记忆补充。

## 工作流程

档位协议以 `agents/jing-xiaowu.md` 的「回答档位」为准。L0 快答按以下顺序选择路径：**路径 A／B（读内置文件、零调用）优先**；内置资料不足以作答时才走路径 C，且只调用知识库 **1 次**；L1+ 每次仅针对用户选定方向追加 **1 次**。不自动串联其他技能。

### 路径 A：G1-G9 路线简单介绍

直接读取 @references/route_overview.md 的「路线速览」与「各线路简介」，**不调用接口**。这是 L0 快答的默认路径。

按「线路定位 → 串联景点 → 起止片区 → 参考总时长」组织回答，一句话简介即可，不要扩展成完整行程单。快答末尾给出 2—3 个可深入方向，例如「该线路主要景点的详细介绍」「适合的主题玩法」「生成完整行程单」，并提示用户回复方向名称或说「展开 XX」，用户点选后再逐层展开。

### 路径 B：景点关联路线介绍

1. 先在 @references/route_overview.md 的「景点 → 路线速查」表中查出该景点所属代号与线路（不调用接口）。
2. L0 快答只回答线路归属；把「了解景点本身」列为可深入方向，用户点选后才走路径 C 追加 1 次知识库调用，不在本轮自动补充。
3. 回答时点明所属线路（代号 + 线路名），并按需列出同线路的其他串联景点。

### 路径 C：调用知识库（景点之外的咨询也走这里）

适用场景：景点详细介绍，以及玩法、主题、季节、对比取舍、讲解词、打卡清单等超出内置文件的咨询。L0 快答**只调用 1 次**，不拆分 query、不补主题、不串联其他技能。

1. 将用户问题改写为一个明确的 `query`（中文）：保留景点名、地点等关键实体与用户的限定词即可，**不再局限于"详细介绍"类问法**，例如 `"武汉大学樱花什么时候开好看"` `"省博物馆和武汉博物馆去哪个"`，也是合法的 query。
2. 执行脚本：

   ```bash
   python3 scripts/query_scenic.py "详细介绍一下东湖绿道"
   ```

   脚本位置相对于本 SKILL.md 为 `scripts/query_scenic.py`。接口固定入参 `inputs = {"type": "point"}`、`response_mode = "blocking"`，除 `query` 外不修改其他字段。

3. 组织 L0 快答：一句话结论 + 不超过 5 条要点，围绕用户真正的问题、只摘取本次 stdout 原文，而不是照搬接口全文；来源标注为「武汉景区知识库」；末尾给 2—3 个可深入方向，并提示用户回复方向名称或说「展开 XX」，给完即结束本轮。用户点选方向后，复用上一条命令 stderr 中的 `conversation_id` 仅追加 1 次调用，给出该方向完整内容：

   ```bash
   WUHAN_SCENIC_DIFY_CONVERSATION_ID=<上次的conversation_id> python3 scripts/query_scenic.py "东湖绿道和周边景点怎么串联"
   ```

   景点类深入档保留历史背景、看点特色、推荐指数与点评、建议停留时长；玩法/季节/对比类从返回资料中提取相关依据。
4. 接口返回的是景区介绍文本而非用户所问的实时信息时，据实作答：「知识库未提供票价/开放时间等信息，建议出行前核实官方渠道」，**不得**把背景介绍当成答案糊弄过去，也不得编造数字。

## 回答约束

1. 默认承接武汉游玩咨询，**不要把问题推给其他技能**；只有明确落在排除项时才引导：`wuhan-intro`（城市历史与地情）、`wuhan-route-query`（需要生成结构化行程单）。点到点导航、实时路况、驾车/公交具体走法不在能力范围内，如实说明并建议用户使用地图 App，不得编造。
2. 一切事实以内置文件或接口返回为准，接口未覆盖的内容明确说明，不要自行补充未经核实的信息（尤其票价、开放时间、交通班次）。
3. 接口返回错误（HTTP 401/404/500 等）时，向用户说明调用失败并给出原始错误信息，不要改用自身记忆回答。
4. 用户问题同时包含景点咨询与路线规划时，L0 快答只答咨询部分，把「生成完整行程单 / 某条线路包含哪些景点」列为可深入方向；仅在用户点选该方向或明确要求生成行程单后才调用 `wuhan-route-query`，不自动串联，也不要在本技能里生成完整行程单。
