# 武汉固定旅游线路查询技能

## 目的

按固定的 9 条线路代号（G1–G9）查询武汉旅游线路，输出可直接使用的结构化行程单。本技能对外只暴露**一个入参变量：线路代号数组**，取值为 G1–G9，允许一次传入多个。所有内容必须来自接口返回结果，不得凭记忆编造。

## 何时使用

用户提出武汉游玩行程、线路安排类问题时使用，典型场景：

- 几日游规划：「推荐武汉 2 日游」「武汉 3 日游怎么安排」
- 指定线路查询：「G1 和 G2 有哪些景点」「内东湖主线怎么玩」
- 景点反查：「黄鹤楼在哪条线路上」
- 行程增补：「2 日游加光谷」「5 日游再加上武昌支线」

武汉城市综合类问题（地理沿革、人口经济、交通教育）使用 `wuhan-intro`；单个景区的深度介绍（开放时间、门票预约、交通到达）使用 `wuhan-scenic-intro`。

## 线路体系

| 代号 | 线路名 | 类型 | 代号 | 线路名 | 类型 |
| --- | --- | --- | --- | --- | --- |
| G1 | 龟蛇主线 | 主线 | G6 | 汉阳主线 | 主线 |
| G2 | 内东湖主线 | 主线 | G7 | 汉口支线 | 支线 |
| G3 | 外东湖主线 | 主线 | G8 | 武昌支线 | 支线 |
| G4 | 武昌主线 | 主线 | G9 | 光谷支线 | 支线 |
| G5 | 汉口主线 | 主线 | | | |

衔接链（输出顺序与行程天数顺序均以此为准，与传入顺序无关）：

```
G1 龟蛇主线 → G2 内东湖主线【可增补 G9】→ G3 外东湖主线
  → G4 武昌主线【可增补 G8】→ G5 汉口主线【可增补 G7】→ G6 汉阳主线
```

完整代号字典、N 日游推导表与景点速查见 @references/route_codes.md。

## 从自然语言解析代号数组

这是本技能的核心步骤，必须先把用户问题解析为代号数组，再调用脚本。

| 用户说法 | 解析为 |
| --- | --- |
| 「推荐武汉 2 日游」 | G1、G2 |
| 「武汉 3 日游」 | G1、G2、G3 |
| 「4 日游」 | G1、G2、G3、G4 |
| 「7 日游」 | G1–G6 + G9 |
| 「G1 和 G2 有哪些景点」 | G1、G2 |
| 「内东湖主线 + 光谷支线」 | G2、G9 |
| 「2 日游加光谷」 | G1、G2、G9 |
| 「5 日游再加武昌支线」 | G1–G5 + G8 |
| 「6 日游加汉口支线」 | G1–G6 + G7 |
| 「黄鹤楼在哪条线」 | 先反查出 G1，再传 G1 |

推导规则：

1. **N 日游**：N ≤ 6 取主线 G1–G6 的前 N 条；N > 6 先取 6 条主线，再按 G9、G8、G7 顺序补足。
2. **直接代号与线路名等价**：「G1、G2」与「龟蛇主线 + 内东湖主线」解析结果相同。
3. **景点反查**：用户提到具体景点时，用 `--find <景点名>` 反查，或查阅 @references/route_codes.md 的景点速查表得到代号。
4. **支线增补**：在已有主线上追加支线时，按挂靠关系插入——G2 后增补 G9、G4 后增补 G8、G5 后增补 G7。
5. **单独点名支线**：用户只提到某条支线时，一并补上其挂靠主线（如「光谷怎么玩」→ 传 G2、G9），保证行程连贯。

## 工作流程

档位协议以 `agents/jing-xiaowu.md` 的「回答档位」为准。本技能在 L0 快答只执行脚本 **1 次**，卡片默认生成、不改为按需。本技能无 `conversation_id` 会话机制，L1 深入档基于同一次脚本 stdout 展开，不要臆造 `*_DIFY_CONVERSATION_ID` 环境变量。

**输出顺序：先文字快答、卡片随后输出。** 文字快答基于 @references/route_codes.md 的代号字典、衔接链与 N 日游推导表（零调用），或基于同一次脚本 stdout 的片区与时长；随后回显卡片路径与完整行程。一次 `--cards` 调用会同时把文字行程单打到 stdout 并写出 HTML 卡片，**禁止为「先文字、后卡片」执行两次脚本**（会重复拉全量记录与下载图片）。

**宿主兜底（优先保证正确性）**：宿主支持「先输出中间文本、再继续工具调用」时，先输出文字快答，再执行脚本、随后补充卡片结果；若中间文本会被判定为本轮结束，则把「文字快答在前、卡片路径与完整行程在后」放进同一条最终回复，不得漏掉卡片。

1. 按上表把用户问题解析为代号数组。N 日游可直接交给脚本推导，复杂组合自行解析后传入。

2. 执行脚本获取行程单（路径相对于本 SKILL.md 所在目录）：

   **默认一律带 `--cards`**：脚本会同时生成 HTML 缩略卡（图片内联、可直接在 WorkBuddy 渲染）并把文字行程单打到 stdout，供你组织回答。卡片文件默认写**当前工作目录**下的 `./wuhan-route-<codes>.html`；**实际调用必须显式传 `--out <工作区绝对路径>.html`**，不要依赖默认路径。

   > **输出路径必须落在工作区内**：预览服务只服务工作区目录，写到 `/tmp` 等临时目录的卡片用预览地址打开会返回 `Forbidden(403)`。因此**始终显式传 `--out <工作区绝对路径>.html`**，脚本会在 stderr 回显写入的绝对路径；若检测到输出落在临时目录会直接给出警告。文件名一律用 ASCII（脚本已默认），中文文件名在部分预览服务下同样会被拒。

   下列命令为写法示意；凡带 `--cards` 的示例，实际执行时**都必须补上 `--out <工作区绝对路径>.html`**（见上方路径约束），仅末尾示例写出了完整形式。

   ```bash
   # 传入解析出的代号（默认出卡片 + 文字行程单）
   python3 scripts/query_route.py --cards G1 G2

   # N 日游：由脚本自动推导
   python3 scripts/query_route.py --cards --days 3

   # 景点反查所属线路
   python3 scripts/query_route.py --cards --find 黄鹤楼

   # 导出全部 9 条线路
   python3 scripts/query_route.py --cards --all

   # 例外：仅当用户明确说明不需要卡片时，才去掉 --cards 与 --out
   python3 scripts/query_route.py G8

   # 不按「排序」重排，保留接口原始顺序（排查数据时用）
   python3 scripts/query_route.py G8 --no-sort

   # 关闭图片链接/嵌图（占位图或无需图片时）
   python3 scripts/query_route.py --cards G1 --no-image

   # 指定卡片输出路径（推荐：工作区内的绝对路径，确保预览可打开）
   python3 scripts/query_route.py --cards --days 3 --out /Users/you/your-workspace/wuhan-3day.html
   ```

   脚本内部会拉取全量记录并在本地按代号过滤，**因此无需也无法在接口层传过滤条件**（详见 @references/api_reference.md）。

   `--cards` 模式会**并发**下载「图片1/2/3」字段并缩放到 220px 后 base64 内联进单文件 HTML，适合直接预览；相同 URL 自动去重。个别图片下载或缩放失败时，该张自动回退为原始外链（交给浏览器再加载一次，仍失败则隐藏），不再让整块显示「图片加载失败」。当检测到**全表图片为同一组占位图**（非按景点区分）时，卡片自动只渲染文字版并标注「图片待后台补齐」，待后台按景点补齐真实配图后自动恢复嵌图——届时你与用户都无需改动任何调用。该模式不再输出「全表占位图」类 stderr 误报。

3. 基于脚本输出组织回答：文字快答在前，卡片路径随后回显。

   - **L0 快答**：一句话结论 + 不超过 5 条要点，按脚本给出的天数列出线路骨架（第几天 / 线路名 / 片区），并保留「片区 / 本线时长 / 景点数」与全程总时长；只摘取 stdout 与 @references/route_codes.md 的原文，不改写事实、不逐条复述全文。末尾给 2—3 个可深入方向，例如「展开第 1 天的完整景点清单」「查看各景点点评与推荐指数」「增加支线后的完整行程」，用户点选后再逐条展开。
   - **L1 深入**：仅针对用户选定方向给出完整逐条内容，并遵守下列全部忠实性要求；已给过的内容不重复。
   - 忠实使用返回的景点名称、类型、停留时长、推荐指数、点评与片区，不得增删或改写事实。
   - 线路内若有图片链接（接口「图片1/2/3」字段），可一并呈现或转成可视化卡片；图片为占位数据时应明确说明「图片为占位图，待后台补齐」，不要当成真实景点图。
   - 线路的先后（第几天）以脚本输出为准；**每条线路内部的景点顺序必须按脚本给出的顺序呈现**——脚本已按接口「排序」字段递增排好，不要自行重排或按推荐指数、类型重新归类。
   - 按脚本给出的天数顺序呈现，保留「片区 / 本线时长 / 景点数」与全程总时长。
   - 需要给出交通或串联建议时，依据各线路的起止片区推导，并明确标注为建议。
   - 用户问的是单条线路时，只呈现该线路内容，不要擅自展开其他线路。

4. 脚本以非零退出码失败时（HTTP 401/404/405/500 或网络异常），向用户说明查询失败并给出原始错误信息，**不得改用自身记忆回答线路内容**。

## 资源

- `scripts/query_route.py`：查询脚本。接受代号位置参数，或 `--days N` / `--find <景点名>` / `--all`；行程内景点按接口「排序」字段递增输出（`--no-sort` 可退回接口原始顺序）。**`--cards` 为默认调用方式**：同时写 HTML 缩略卡文件并把文字行程单打到 stdout；图片默认并发预取后内联（单张失败自动回退外链），占位图数据下自动降级为文字版（`--no-image` 可彻底关闭图片）。拉取条数、排序、图片预取成功/失败数与图片字段异常提示输出到 stderr。
- @references/route_codes.md：代号字典、衔接链、N 日游推导表、景点→代号速查，解析自然语言时查阅。
- @references/api_reference.md：接口地址、请求体、响应结构与字段类型差异、错误码与环境变量，排查调用问题时查阅。
